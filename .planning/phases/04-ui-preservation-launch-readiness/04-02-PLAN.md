Create `tests/ui-preservation.spec.ts` with three viewport configurations and state machine progression tests.

The test file must:

1. Import from `@playwright/test` and define three viewport sizes as constants:
```typescript
const VIEWPORTS = {
  desktop: { width: 1280, height: 720 },
  tablet: { width: 768, height: 1024 },
  mobile: { width: 375, height: 667 },
};
```

2. Create a `test.describe` block for each viewport. For each viewport, use `test.use({ viewport: VIEWPORTS[name] })` to set the viewport.

3. Each viewport describe block should contain these tests:

**Test: "terminal renders with starfield background"**
- Navigate to `http://localhost:3000`
- Assert canvas element is visible (the Starfield)
- Assert a terminal container div is visible

**Test: "state machine progresses BOOTING -> STATUS -> MENU"**
- Navigate to `http://localhost:3000`
- Wait for the CognitiveStatus dashboard text to appear (look for text "COGNITIVE FUNCTIONS" or "Operating Model" — this indicates STATUS state has been reached)
- Wait for the command input to appear (`aria-label="Terminal command input"`) — this indicates MENU state
- Assert the input is visible and enabled
- Timeout: 15s (typewriter takes several seconds)

**Test: "typing 1 + Enter progresses to voice interface"**
- Navigate to `http://localhost:3000`
- Wait for command input (aria-label="Terminal command input") to be visible (15s timeout)
- Type "1" into the input
- Press Enter
- Wait for the voice interface connect button to appear (look for button containing "Connect" text, 10s timeout)
- Assert the connect button is visible

**Test: "terminal has correct max-width for viewport"** (desktop only)
- Navigate and wait for terminal to render
- Get the terminal container's computed width
- Assert it does not exceed 860px

**Test: "terminal uses 95vw on mobile"** (mobile only)
- Navigate and wait for terminal to render
- Get the terminal container's computed width
- Assert width is approximately `375 * 0.95 = 356px` (within 5px tolerance)

Use `test.setTimeout(30000)` at the describe level since typewriter animations take time.

Follow the existing test patterns from `tests/realtime-voice.spec.ts` for console log labeling (use `[ui]` prefix).
