This task requires human action because Alibaba Cloud and Vercel dashboard operations need authenticated access.

**Step 1: Provision an Alibaba Cloud ECS instance**

Using your $300 free credits:
- Go to https://ecs.console.aliyun.com/
- Create a lightweight ECS instance (e.g., ecs.t6-c1m1.large — 1 vCPU, 1GB RAM is plenty for a Bun WS server)
- Region: pick one close to your target audience (Singapore `ap-southeast-1` is good for low-latency DashScope API calls since DashScope servers are in Alibaba's network)
- OS: Ubuntu 22.04 or Alibaba Cloud Linux 3
- Open security group ports: 443 (HTTPS/WSS) and 22 (SSH)

**Step 2: Install Bun and deploy ws-server**

SSH into the instance and run:
```bash
# Install Bun
curl -fsSL https://bun.sh/install | bash
source ~/.bashrc

# Clone and install
git clone https://github.com/Kaleb-Nim/nim-kaleb.git
cd nim-kaleb/ws-server
bun install
```

Create env file on the server:
```bash
cat > .env.local << 'EOF'
DASHSCOPE_API_KEY=sk-689ad643166e4986b26b6a34bfbb5297
DASHSCOPE_VOICE_ID=qwen-tts-vc-kaleb-voice-20260409131147531-d171
PORT=8080
EOF
```

Run the server (use a process manager like `pm2` or `systemd` for persistence):
```bash
# Quick test
bun run src/index.ts

# For persistence with pm2:
bun add -g pm2
pm2 start --interpreter bun src/index.ts --name ws-server
pm2 save
pm2 startup
```

**Step 3: Set up TLS (wss://) with a reverse proxy**

The browser requires `wss://` (not `ws://`) since the frontend is on HTTPS. Options:

Option A — Nginx reverse proxy (recommended):
```bash
sudo apt install nginx certbot python3-certbot-nginx
# Point a subdomain (e.g., ws.nim-kaleb.com) to the ECS public IP
# Then:
sudo certbot --nginx -d ws.nim-kaleb.com
```

Nginx config (`/etc/nginx/sites-available/ws`):
```nginx
server {
    listen 443 ssl;
    server_name ws.nim-kaleb.com;

    ssl_certificate /etc/letsencrypt/live/ws.nim-kaleb.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ws.nim-kaleb.com/privkey.pem;

    location /ws {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400;
    }

    location /health {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

Option B — Alibaba Cloud ALB (Application Load Balancer) with managed TLS certificate.

**Step 4: Verify the WS server is reachable**

```bash
curl https://ws.nim-kaleb.com/health
# Should return: ok
```

**Step 5: Set env vars on Vercel**

Go to https://vercel.com/ -> nim-kaleb project -> Settings -> Environment Variables:
- Set `NEXT_PUBLIC_WS_SERVER_URL` = `wss://ws.nim-kaleb.com` (your actual domain)
- This var is inlined at build time, so you MUST trigger a redeploy after setting it

**Step 6: Decide branch deployment**

Decide whether to:
- (A) Merge `feat/openai-realtime` to `main` and deploy from main
- (B) Deploy the `feat/openai-realtime` branch directly (Vercel supports branch deploys)

If merging to main: `git checkout main && git merge feat/openai-realtime && git push origin main`

**Step 7: Trigger production build**

After env vars are set, trigger a new Vercel deployment so `NEXT_PUBLIC_WS_SERVER_URL` is baked into the build.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Alibaba Cloud WS | WebSocket crosses from user browser to ECS; must use wss:// (TLS) |
| Alibaba Cloud -> DashScope | Server-side API calls with DASHSCOPE_API_KEY; key never exposed to browser |
| Vercel build -> env vars | NEXT_PUBLIC_WS_SERVER_URL baked at build time; only contains the public WS URL (not a secret) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Information Disclosure | DASHSCOPE_API_KEY | mitigate | Key is set only on ECS env vars (server-side), never in NEXT_PUBLIC_* or browser bundles |
| T-04-05 | Tampering | Mixed content (ws:// on HTTPS) | mitigate | NEXT_PUBLIC_WS_SERVER_URL must use wss:// protocol; Nginx terminates TLS |
| T-04-06 | Denial of Service | ECS WS server | accept | Single-instance ECS; acceptable for portfolio traffic levels. Alibaba Cloud security groups limit access to ports 443/22 only |
</threat_model>
