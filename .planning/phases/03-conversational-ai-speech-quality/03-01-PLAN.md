## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Bun WS server | Untrusted audio and text from visitor crosses into server pipeline |
| Bun WS server -> DashScope APIs | Server forwards processed data to external APIs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | session.ts barge-in filter | accept | Barge-in filter is a UX optimization, not a security boundary. No auth implications — visitor already has an active session. |
| T-03-02 | Tampering | system-prompt.md | mitigate | Guardrails section in system prompt prevents prompt injection. Existing guardrails instruct model to stay in character and reject identity overrides. No changes to guardrails in this plan. |
| T-03-03 | Denial of Service | asr.ts silence_duration_ms increase | accept | Increasing silence timeout from 400ms to 1000ms slightly increases ASR session duration per turn. Cost impact is negligible — DashScope ASR billing is per-audio-second, not per-connection-second. |
| T-03-04 | Information Disclosure | llm.ts bargeInPrefix | accept | The "Oh sure -- " prefix is a static string injected server-side. No user data is exposed. The prefix appears in the LLM response which is intentionally sent to the visitor. |
</threat_model>
