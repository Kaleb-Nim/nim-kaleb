    2. Inspect what Production currently has:
       `bunx vercel env ls production`
       Capture the list of variable NAMES (not values) for the SUMMARY.

    3. Pull production values locally to a temp file (gitignored automatically, but verify):
       `bunx vercel env pull .env.production.local --environment=production`
       Then immediately confirm `.env.production.local` is gitignored:
       `git check-ignore .env.production.local` (must exit 0). If NOT ignored, STOP and add it to `.gitignore` before proceeding.

    4. For each of the three required runtime vars, add to Preview scope by reading the value from `.env.production.local` and piping into `bunx vercel env add`:

       ```bash
       grep '^OPENAI_API_KEY=' .env.production.local | cut -d= -f2- | tr -d '"' | bunx vercel env add OPENAI_API_KEY preview
       grep '^NEXT_PUBLIC_WS_SERVER_URL=' .env.production.local | cut -d= -f2- | tr -d '"' | bunx vercel env add NEXT_PUBLIC_WS_SERVER_URL preview
       grep '^DATABASE_URL=' .env.production.local | cut -d= -f2- | tr -d '"' | bunx vercel env add DATABASE_URL preview
       ```

       (If `bunx vercel env add` does not accept stdin reliably in this CLI version, fall back to invoking it once per var and pasting the value at the interactive prompt — this is acceptable; the values came from `.env.production.local` which is gitignored.)

       If any of the three vars are MISSING from `.env.production.local`, do NOT invent values — abort and report in SUMMARY. The DASHSCOPE_API_KEY and DASHSCOPE_VOICE_ID are ECS-only (per README env table) and MUST NOT be added to Vercel.

    5. Mirror any ADDITIONAL Vercel-scope vars found in step 2 that the codebase actually reads (verify via the grep in `read_first`). Do NOT mirror vars unused by app code.

    6. Clean up: `rm .env.production.local` (do not leave secrets on disk longer than necessary).

    7. Verify Preview scope: `bunx vercel env ls preview` — capture output for SUMMARY.
  </action>
