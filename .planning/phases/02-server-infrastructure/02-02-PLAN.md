Export `streamLlmResponse(transcript: string, conversationHistory: Array<{role: string, content: string}>, onChunk: (text: string) => void, onDone: () => void, onError: (msg: string) => void): Promise<void>`:
- Build messages array: `[{ role: 'system', content: systemPrompt }, ...conversationHistory, { role: 'user', content: transcript }]`
- Call `client.chat.completions.create({ model: 'qwen-plus', stream: true, messages })`
- Iterate with `for await (const chunk of stream)`:
  - Extract `token = chunk.choices[0]?.delta?.content ?? ''`
  - Accumulate into a `buffer` string
  - Flush to `onChunk(buffer)` and reset buffer when: `buffer` matches `/[.!?]\s/` (sentence boundary) OR `buffer.length > 80` (max chunk size for low latency)
- After loop, flush remaining buffer if non-empty
- Call `onDone()` after all tokens processed
- Wrap entire function in try/catch, call `onError(err.message)` on failure
- Log `[llm] streaming started for: "${transcript.slice(0, 50)}..."` at start
- Log `[llm] streaming complete` at end

**ws-server/src/dashscope/tts.ts** — DashScope TTS WebSocket client:

```typescript
export interface TtsCallbacks {
  onAudioDelta: (base64Audio: string) => void;
  onDone: () => void;
  onError: (message: string) => void;
}
```

Export `createTtsSession(callbacks: TtsCallbacks): WebSocket`:
- Open WebSocket to `wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime?model=qwen3-tts-vc-realtime-2026-01-15`
- Authorization header: `Bearer ${process.env.DASHSCOPE_API_KEY}`
- On open, send `session.update`:
  ```json
  {
    "type": "session.update",
    "event_id": "evt_tts_init",
    "session": {
      "mode": "server_commit",
      "voice": process.env.DASHSCOPE_VOICE_ID,
      "language_type": "Auto",
      "response_format": "pcm",
      "sample_rate": 24000
    }
  }
  ```
- On message, parse JSON and route:
  - `response.audio.delta` -> call `callbacks.onAudioDelta(msg.delta)`
  - `response.done` -> call `callbacks.onDone()`
  - `error` -> call `callbacks.onError(msg.error?.message ?? 'TTS error')`
- On close, log `[tts] WebSocket closed`
- On error, call `callbacks.onError('TTS WebSocket connection error')`

Export `appendTextToTts(ttsWs: WebSocket, text: string): void`:
- Send `{ type: 'input_text_buffer.append', event_id: 'evt_tts_' + Date.now(), text }` as JSON
- Only send if `ttsWs.readyState === WebSocket.OPEN`

Export `finishTtsSession(ttsWs: WebSocket): void`:
- Send `{ type: 'session.finish', event_id: 'evt_tts_finish' }` as JSON

CRITICAL: Use `process.env.DASHSCOPE_VOICE_ID` (value: `qwen-tts-vc-kaleb-voice-20260409131147531-d171`). This is the voice_id from Phase 1 enrollment. Using any other voice_id or model will produce wrong voice or errors.

CRITICAL: TTS model MUST be `qwen3-tts-vc-realtime-2026-01-15` in the WebSocket URL. This is the model the voice was enrolled against. Cross-model incompatibility confirmed in Phase 1.

When ASR produces a final transcript, trigger the LLM->TTS cascade:

1. Send `transcript.final` to browser (already done in Plan 01)
2. Add `{ role: 'user', content: transcript }` to `conversationHistory`
3. Open TTS WebSocket session via `createTtsSession()` with callbacks:
   - `onAudioDelta: (delta) => this.send({ type: 'response.audio.delta', delta })`
   - `onDone: () => { this.send({ type: 'response.done' }); this.ttsWs = null; }`
   - `onError: (msg) => this.send({ type: 'error', message: msg })`
4. Store TTS WS in `this.ttsWs`
5. Wait for TTS WS to be open (check readyState, use small polling interval or wrap onopen in a Promise)
6. Call `streamLlmResponse()` with:

   - `onDone: () => { finishTtsSession(this.ttsWs!); /* accumulate assistant response into conversationHistory */ }`
   - `onError: (msg) => this.send({ type: 'error', message: msg })`
7. Track the full LLM response text to add to `conversationHistory` as assistant message after onDone

**Update cleanup():**
- Close TTS WebSocket if open (`this.ttsWs?.close()`)
- Clear conversation history

**Key architecture note:** The streaming overlap works because:
- LLM `onChunk` fires per sentence boundary -> immediately calls `appendTextToTts`
- TTS processes text as it arrives (server_commit mode) and fires `onAudioDelta` -> immediately forwarded to browser
- Browser's existing `scheduleAudioChunk` handles playback scheduling
- Result: first audio reaches browser ~450-550ms after ASR transcript (within 800ms budget)
