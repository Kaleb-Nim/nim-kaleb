New `MeetupItem` after this plan:
```typescript
export interface Speaker {
  name: string;
  role: string;
  linkedin: string;
}

export interface MeetupItem {
  num: number;                          // 1..11 — drives the [#NN] gold chip
  date: string;                         // e.g. 'Mar 2025', 'Apr 2026'
  title: string;                        // topic only; "Meetup #N" is rendered from `num`
  desc: string;                         // 1-3 sentence description
  speakers: Speaker[];                  // >= 1 speaker; may be empty array only when no speakers existed
  hero: string | null;                  // public path '/meetups/<slug>-hero.jpg' or null for placeholder
  gallery: Array<string | null>;        // remaining photos (post-hero); null entries render as placeholders
  signup?: string;                      // optional external sign-up URL (used for March 2025 entry)
}
```

`Section.items` union must include the new `MeetupItem[]` shape — the union
already references `MeetupItem[]`, so changing the interface in-place
automatically updates the union (no Section type edit needed).

Source-of-truth shape for the data (from `.planning/research/v3-design-kit/index-data-v2.jsx`
lines 62-183) uses `images: Array<string|null>` where `images[0]` is hero and
`images[1..]` are gallery. We split that into explicit `hero` + `gallery` so
TypeScript and the MeetupsPage component (Plan 02) don't have to repeatedly
destructure `images[0]` / `images.slice(1)`.
